### POST /api/ask runs cross-site CORS-simple requests, charging the visitor's anonymous quota and the operator's provider spend

Fingerprint `tramitico/ask/anon-cross-site-admission-no-origin-gate` · severity **low** (likelihood low: It is trivial to mount from any page with traffic and needs no account and no attacker-owned IPs. But the attacker cannot read any answer, and each forged ask counts only if the visitor's page stays open until the stream completes. The payoff is griefing: burning the operator's spend and denying visitors their free quota. Impact medium: Each forged ask runs the full paid pipeline on the operator's prepaid keys: condense when history is supplied, embed, Voyage rerank, and the Anthropic answer, with one retry possible. The total grows with attacker page traffic, bounded only per visitor (10 per browser family and 30 per IP per day); the source has no global ceiling. Visitors and their same-family NAT neighbours lose the day's allowance, observed as a 429. No data is exposed or modified.) · confidence high · hunter `h01-xorigin` · Phase 3 `v02` (confirmed) · Phase 5 `p02` (verified)

**Lower-trust principal** The operator of any third-party web page, with no tramitico account, acting through visitors' browsers.

Any third-party page can make a visitor's browser send a cross-site POST to /api/ask as a CORS-simple request, and the route runs it in full. Two request shapes work: a hidden form with enctype=text/plain whose field name carries the JSON, or a fetch with mode no-cors and a string body. Browsers send both without a preflight. The auth cookie is SameSite=Lax, so the browser withholds it and the request takes the anonymous path. The route parses the body with request.json(), which ignores Content-Type, and never reads Origin, Referer or Sec-Fetch-Site. It charges the ask to the visitor's HMAC(date|IP|UA family) subject and to their per-IP umbrella. It then runs the paid pipeline on the operator's keys: condense (the form shape can carry a history array, which triggers the condense call), embed and retrieve, the Voyage rerank, and the Anthropic answer. The attacker cannot read the answer. There are two effects. (1) The visitor, and anyone behind the same NAT or CGNAT address using the same browser family, loses the free daily allowance; the visitor's own first ask afterwards gets a 429. (2) Operator-paid provider work grows with the attacker page's traffic: up to 10 full asks per visiting browser family and 30 per IP per CR day, with no attacker-owned IP address involved. The quota is kept only if the forged request stays connected until the answer finishes. If the page closes early, the client-abort path refunds both rows (route.ts:714-719), but provider work already started is still spent. This is distinct from the owner-accepted #358 row 6 (UA-family buckets): the root cause here is the missing request-origin binding, not how the subject is derived.

**Root cause** The only unauthenticated, spend-bearing endpoint treats ambient request properties as the anonymous principal: the client IP (first X-Forwarded-For hop) and the User-Agent family. Any page can make a visitor's browser present both. Yet the route has no request-side same-origin binding. POST (route.ts:598-608) calls request.json() without checking Content-Type (a JSON-only requirement would force a CORS preflight that the route never answers), and it checks neither Origin nor Sec-Fetch-Site. The proxy only refreshes the session and passes the request on. next.config.ts sets only response headers. Next 16.3.5's Origin check covers Server Actions only (action-handler.js:450), not route handlers.

**Conditions**

- _user_interaction_ — A visitor loads an attacker-controlled or attacker-injected page, such as a hidden auto-submitting text/plain form in an iframe or a script calling fetch with mode no-cors. No interaction with tramitico is needed. The forged request must stay connected until the answer completes for the quota charge to stick; an early disconnect refunds the rows, but provider work already done is still spent.
- _authentication_level_ — None. The forged ask is anonymous. The visitor's session cookie is neither needed nor sent.
- _system_configuration_ — The production quota defaults apply: 10 anonymous asks per subject and 30 per IP per CR day, with the answer model and rerank enabled. No Vercel Firewall or bot-protection rule blocks cross-site POSTs to /api/ask. Platform firewall state is not in the repository; none is configured in source (there is no vercel.json).
- _network_routing_ — Visitors who share a NAT or CGNAT address and a browser family share the subject row that the forged asks exhaust, and every visitor on that IP shares the umbrella.

**Bounded reproduction** (full detail in `FINDINGS-DETAIL.md`)

- `<form method="post" enctype="text/plain" action="https://<host>/api/ask"><input type="hidden" name='{"question":"¿Qué es el régimen simplificado?","history":[{"question":"hola","answer":"Buenas"}],"p":"' value='"}'></form> → body {"question":"¿Qué es el régimen simplificado?","history":[{"question":"hola","answer":"Buenas"}],"p":"="}\r\n, Content-Type text/plain`
- `fetch('https://<host>/api/ask', {method: 'POST', mode: 'no-cors', body: '{"question":"¿Qué es el régimen simplificado?"}'}) → Content-Type text/plain;charset=UTF-8`
- `Harness request headers: origin https://evil.example, referer https://evil.example/page, sec-fetch-site cross-site, user-agent Chrome/141 (macOS), x-forwarded-for 198.51.100.23, no cookie, no authorization`

**Observed** The proxy returned 200 with x-middleware-next 1, and getUserId returned null. The text/plain form shape (with history) returned 200 and incremented exactly anon(visitorIP,Chrome)=1 and anon-ip(visitorIP)=1, with 0 refunds. It made 1 condense model call, 1 retrieve, 1 rerank and 1 answer doStream, and data-citations appeared on the stream. The no-cors fetch shape gave the same result without the condense call. Control: a cross-site application/x-www-form-urlencoded body got a 400 with 0 increments. After 10 forged no-cors asks (all 200, 10 answer doStream calls), the visitor's own same-origin application/json ask returned 429 rate_limited. Result file: agents/v02/artifacts/out/v02-xsite.txt.

**Smallest fix** Reject cross-site and non-JSON asks before request.json() and before any quota or paid work. First, require Content-Type application/json. This makes any cross-origin browser call non-simple, so its preflight fails because the route sends no CORS headers. Second, reject when Sec-Fetch-Site is present and is not same-origin. Third, reject when Origin is present and matches neither the request's own origin nor NEXT_PUBLIC_SITE_URL. Non-browser clients that send neither header can only spend their own IP's quota, so they stay allowed. The first-party DefaultChatTransport and the Playwright e2e callers (request.post with data) already send application/json. Regression test: a text/plain body with Origin https://attacker.example and Sec-Fetch-Site cross-site gets a 4xx, and checkRateLimit, retrieve and the model are never called; a same-origin application/json ask still streams.
