# ADR 0018 — Derived figures are computed by code

Date: 2026-09-04 · Status: accepted · Amends [SPEC §5](../../SPEC.md#5-retrieval--answer-assembly) · Context: issue [#263](https://github.com/rjwrld/tramitico/issues/263)

Some useful figures are not claims any one official document makes. The 2026 CCSS base mínima contributiva, for example, combines a CCSS scale factor with the MTSS minimum wage. We record these derivations in `corpus/manifest.json` as arithmetic formulas over named values, with the exact document and artículo that state every input.

After reranking, answer assembly resolves each input against the final numbered chunks. It evaluates and exposes the figure only when every input is present, using a deliberately small arithmetic grammar rather than executable manifest code. The calculated block carries the existing citation marker of every input, so model prose, sellos, and history use the ordinary citation path. Runtime validation rejects a quoted figure unless its own sentence carries every input marker, and the groundedness judge receives the same calculated block as the answer model. Prompt rule 3 remains unchanged: the model may repeat a system-calculated figure but may not calculate, estimate, or update one itself.

The manifest is intentionally the update seam for annual figures. A new wage decree or salario base requires updating its audited input value and source identity together; a partial retrieval or stale article identity yields no derived block rather than an unsupported number.

## Amendment (2026-09-04, issue [#287](https://github.com/rjwrld/tramitico/issues/287))

"Every input present in the final numbered chunks" is unchanged; what the final numbered chunks _are_ is not. The 2026 baseline (#267) lost the IVM base to the rerank cut alone: `ccss-cuanto-pago-base` retrieved `ccss-escala-ivm` «Artículo 4°, sesión 9570» and the reranker dropped `salarios-minimos` «Artículo 1» between the pool of 40 and the top 8, so the figure a reader asked for silently did not exist. A figure is arithmetic over every one of its inputs, which makes losing one chunk not a weaker answer but a deleted one.

So when at least one input survived the cut and the corpus can complete the figure, `pinDerivedFigureInputs` appends the missing inputs from the fused pool the reranker just read, before resolution runs. It appends and never substitutes: the answer set the rerank chose stays intact, existing citation markers keep their positions, and a pinned chunk is an ordinary numbered source, cited and validated like any other. The paragraph above still governs everything else — a figure with no input retrieved at all is not this question's figure and is never assembled, an input the corpus cannot supply still yields no derived block, and the prompt rule 3 prohibition on the model calculating anything is untouched.

The pin ships **off**. Deterministic and append-only makes it safe to try, not measured: the guard is source identity, not question relevance, so an artículo that survived some unrelated question can pull its figure's siblings in behind it — the append cannot move a citation marker, but it can move an answer, its token count and its latency. #287 asked for options «to measure, not guess», and its acceptance is a measurement. So `PIN_DERIVED_INPUTS=on` is what the next authorized run turns on, on both sides of an otherwise fixed comparison (same corpus, same models, same top-k), and a measured result — F1's two BMC inputs resolved, hit-rate still at or above the gate, groundedness, adequacy and abstention unharmed — is what may make it the default. Until then the pipeline of record is the one this ADR described before this amendment.

## Amendment (2026-09-07, issue [#312](https://github.com/rjwrld/tramitico/issues/312))

The pin appends from **the fused pool the reranker just read**, and until now that pool did not hold the chunk it needed. `salarios-minimos` «Artículo 1» sat at fused #122 on `ccss-cuanto-pago-base` and #46–#130 on the other BMC cases — found by one lexical leg of the expansion and nothing else — so the option #287 shipped could not fire on the very case that motivated it. #304's authorized run recorded F1 failing in all three of its configurations for that reason, and read as "unchanged by the catalogue" what was in fact "unreachable by the pin". The pool half is fixed in the step catalogue (`eval/step-catalogue.json`, T1-B and T1-F carry the decree's table line as a fourth sentence); this ADR's guard, grammar and citation contract are untouched.

The pin still ships **off**, and the amendment above still states the bar. What #312 adds is the part of that bar a deterministic probe can reach. Over every single-turn case in `eval/dataset.jsonl`, resolving the figures with the pin off and on, the append fires on exactly four cases — `ccss-cuanto-pago-base`, `ho-minimo-caja-independiente-2026`, `ho-800-mil-que-porcentaje-caja`, `ho-desde-cuanta-plata-caja` — adds exactly one chunk to each, and leaves every other answer set byte-identical. All four already name `salarios-minimos` art. 1 in their `expected`. The risk this ADR named — source identity pulling siblings into an unrelated answer — does not occur anywhere in the dataset; what remains for the authorized run is groundedness, adequacy and abstention, which no probe can read. Before #312 that run had nothing to compare: `PIN_DERIVED_INPUTS=on` and `off` produced the same answer set on F1.

## Amendment (2026-09-15, issue [#305](https://github.com/rjwrld/tramitico/issues/305))

The authorized run this ADR has been waiting for happened, and read the pin on the only cases whose answer set it changes. Over every single-turn case, at top 8 and at top 10, `PIN_DERIVED_INPUTS=on` appends `salarios-minimos` «Artículo 1» to `ccss-cuanto-pago-base`, `ho-desde-cuanta-plata-caja` and `ho-800-mil-que-porcentaje-caja` (and, at top 8 only, `ho-minimo-caja-independiente-2026`, whose input the wider cut already holds) and leaves every other answer set byte-identical; on the abstention lane it resolves nothing. Under `ANSWER_TOP_K=10` those three answers are grounded 3/3, F1 resolves, states and completely cites both BMC figures (¢324.590 with markers {8, 11}, ¢346.789 with {2, 11}) — the first F1 pass since #296 — and the abstention lane is 9/9 with no figure on any ABS case. That is the bar this ADR set, met at top 10.

Top 10 does not ship (`eval/README.md`, «The authorized full run», #305: it costs the groundedness gate), and at the shipped top 8 the IVM input `ccss-escala-ivm` sits on either side of the cut from run to run — outside it on the reading the same day's arm A got — so at 8 the pin can complete the SEM figure and only sometimes the IVM one. The rule stands: a full run on both sides of the shipped top-k. The pin stays **off**; what remains unmeasured is narrower than before (groundedness and adequacy of three answers at top 8), and what F1 actually needs is a rerank that keeps `ccss-escala-ivm` inside eight, which is #287's question, not this ADR's.

## Amendment (2026-09-15, the pin at top 8)

The half of the bar #305 left open was read the same day, at the shipped `ANSWER_TOP_K=8`, on the four cases the probe says the pin changes there (`ccss-cuanto-pago-base`, `ho-desde-cuanta-plata-caja`, `ho-800-mil-que-porcentaje-caja`, `ho-minimo-caja-independiente-2026`) plus the whole abstention lane, with `PIN_DERIVED_INPUTS=on` and everything else the pipeline of record (`eval/README.md`, «The pin at top 8»). Groundedness 4/4; the runtime citation invariant holds on all four; every derived figure the answers state carries both of its input markers — six mentions, «¢346.789 [5][9]», «¢324.590 [7][9]» and the like — and the abstention lane is 9/9 with no figure on any ABS case. `ho-minimo-caja-independiente-2026` and `ho-800-mil-que-porcentaje-caja` resolve and cite both BMC figures at 8; `ho-desde-cuanta-plata-caja` the SEM one its set holds; F1 resolves SEM only, because `ccss-escala-ivm` sat outside the cut on this reading as it did on arm A's — the reranker question #287 owns, which no pin can answer.

**The pin ships on.** The risk this ADR named — an append pulling siblings into an unrelated answer — does not occur on the dataset (the probe), and on the four answers it does change the pin is grounded, completely cited and abstention-clean at both top‑ks it has been read at. `pinDerivedFigureInputs` reads `PIN_DERIVED_INPUTS` the way `rerank.ts` and `expand.ts` read theirs: unset or empty is on, `off` is the measured baseline. What the ADR still does not claim is F1 green at 8 — that stays red on the strict «both BMC figures» assertion until #287 keeps the IVM input inside eight — and the full-run rule is unchanged for the next knob: this amendment rests on a scoped read of the only answers the pin touches, which the probe makes sufficient for _this_ change and for no other.

**What counts as a quote (2026-09-23, #403).** The runtime check read "its own paragraph" as the text from the figure to the next sentence end or line break, and found the figure by prefix. #401's `ccss-faq` transcription made the prefix wrong: its escala tables carry «hasta ₡324,590.999» and «hasta ₡346,789.999», a T1-F draft copies them as «hasta ¢324.590,999», and the check read each table row as an uncited BMC quote — seven of ten correctly cited local drafts refused. A quote is now the figure as a whole number (a following digit, or `,`/`.` and a digit, makes it a longer number, except zero decimals), and ₡ reads as ¢, which a draft that wrote ₡ had escaped entirely. The contract is unchanged: every sentence that quotes a figure carries every input marker, now checked on every such sentence and on nothing else. Evidence in `eval/runs/2026-09-23-t1f-derived-check/`.
